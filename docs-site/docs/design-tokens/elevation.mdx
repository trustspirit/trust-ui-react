# Elevation

trust-ui v2 has exactly one shadow.

```css
--tui-shadow-overlay: 0 1px 1px rgba(0, 0, 0, 0.04), 0 10px 30px -12px rgba(0, 0, 0, 0.22); /* light */
--tui-shadow-overlay: 0 10px 30px -12px rgba(0, 0, 0, 0.7);                                 /* dark */
```

It's a semantic token, defined per theme like any color — not a scale, not a palette value. There is nothing to pick between; a component either uses `--tui-shadow-overlay` or it uses no shadow at all.

## Who gets to use it

Only components that are genuinely floating above the page — rendered outside normal document flow, dismissable, temporary:

- Dialog
- Menu
- Select (its popover)
- Toast
- ActionSheet
- BottomSheet

Nothing else casts a shadow. A Card, a Table row, a Panel, a Button — none of these are actually floating, so none of them get one. If a component you're building isn't in the list above, don't reach for `--tui-shadow-overlay`.

## Hierarchy comes from rules, not shadows

Everywhere outside that list, visual separation between surfaces is drawn with a border, not a shadow: `--tui-rule` for a normal division, `--tui-rule-strong` where the separation needs to read more strongly. Two flat surfaces sitting side by side are told apart by the color of the line between them, not by one of them appearing to float above the other. See [Colors](./colors.mdx#rule) for both tokens.
