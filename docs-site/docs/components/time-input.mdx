# TimeInput

A time-of-day field. The value is always a 24-hour `'HH:mm'` string (or `null`), whatever clock is displayed.

## 12-hour clock and locale

Without `hourCycle`, the clock follows `locale` (and the runtime's default locale when `locale` is not set either). The AM/PM names and their position come from the locale too.

<ComponentPreview code={`<TimeInput label="Reminder" hourCycle={12} locale="en-US" defaultValue="15:30" />
<TimeInput label="알림 시각" locale="ko-KR" defaultValue="15:30" />`}>
  <div style={{ display: 'flex', gap: 16, flexWrap: 'wrap' }}>
    <TimeInput label="Reminder" hourCycle={12} locale="en-US" defaultValue="15:30" />
    <TimeInput label="알림 시각" locale="ko-KR" defaultValue="15:30" />
  </div>
</ComponentPreview>

When rendering on a server, pass `hourCycle` or `locale` explicitly. Otherwise the server and the browser may resolve different default locales and render different segments.

## Min, max and step

A time outside `min`/`max` is never reported through `onChange`. While the segments show such a time the field is marked invalid, and on leaving the field it moves to the nearest allowed time. `step` is the minute increment of the arrow keys (and of the native picker); typed minutes are not snapped.

<ComponentPreview code={`<TimeInput
  label="Transfer time"
  hourCycle={24}
  defaultValue="10:00"
  min="09:00"
  max="15:30"
  step={15}
  helperText="Between 09:00 and 15:30"
/>`}>

## Value behaviour

- `onChange` receives `null` until both the hour and the minute are set, then `'HH:mm'`.
- With `name`, the `'HH:mm'` value is submitted (through a hidden input in the segmented rendering).

## Accessibility

On fine pointers the field is a `group` named by the label and described by the helper text or error message. Inside it, the hour, the minute and (on a 12-hour clock) AM/PM are separate `spinbutton` segments with `aria-valuenow`, `aria-valuemin`, `aria-valuemax` and `aria-valuetext`. `aria-invalid` and `aria-required` are set on the segments. Segment names are overridable (`hourLabel`, `minuteLabel`, `periodLabel`, `emptyValueText`).

| Key | Action |
| --- | --- |
| `ArrowUp` / `ArrowDown` | Increase / decrease the focused segment, wrapping at the ends |
| `0`–`9` | Type into the segment; focus advances when the segment is complete |
| `ArrowLeft` / `ArrowRight` | Previous / next segment |
| `:` | Next segment |
| `Backspace` / `Delete` | Clear the segment (`Backspace` on an empty segment moves back) |
| `Home` / `End` | Lowest / highest value of the segment |
| `A` / `P` | AM / PM on the AM/PM segment |
| `Tab` | Next segment, then out of the field |

Key handling is skipped during IME composition.

## Mobile

- On touch devices a native time input is rendered, so the OS time picker is used. `min`, `max` and `step` (converted to seconds) are passed through, and the label is tied to it with `htmlFor`.
- The iOS picker does not enforce `min`/`max`; the component does, the same way as in the segmented rendering.
- The field height follows the control height tokens (`--tui-control-md` for the default size), which are at least 44px under `(pointer: coarse)`. The `sm` size keeps a 16px font so iOS does not zoom on focus.
