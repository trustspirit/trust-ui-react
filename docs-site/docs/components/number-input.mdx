# NumberInput

A numeric field with keyboard stepping, range clamping and optional locale formatting. The value is a `number` (or `null` when empty), not a string.

## Step, precision and units

`precision` defaults to the decimal places of `step`. Values are rounded to it when stepping and on blur, so repeated steps do not accumulate floating-point error (0.1 + 0.2 gives 0.3).

<ComponentPreview code={`<NumberInput label="Interest rate" defaultValue={3.5} step={0.1} min={0} max={20} units="%" />`}>
  <NumberInput label="Interest rate" defaultValue={3.5} step={0.1} min={0} max={20} units="%" />
</ComponentPreview>

## Formatted display

With `formatOptions`, the value is formatted through `Intl.NumberFormat` while the input is not focused. On focus the raw number is shown for editing.

## Value behaviour

- While typing, `onChange` receives the parsed number as it is, so you can validate live. Partial text such as `-` or `1.` stays in the input; `-` alone reports `null`.
- On blur and when stepping, the value is clamped to `min`/`max` and rounded to `precision`, and `onChange` fires again if that changed it.
- An empty input is `null`.
- With `name`, the unformatted number is submitted through a hidden input.
- The mouse wheel never changes the value.

## Accessibility

- Role: `spinbutton` on a text input, named by the label, with `aria-valuenow`, `aria-valuemin`, `aria-valuemax`. `aria-valuetext` carries the formatted value (and string `units`).
- Helper text and error message are linked with `aria-describedby`; the error state sets `aria-invalid`.
- The stepper buttons have accessible names (`incrementLabel`, `decrementLabel`) and are left out of the tab order because the arrow keys do the same job.

| Key | Action |
| --- | --- |
| `ArrowUp` / `ArrowDown` | Add / remove one `step` |
| `PageUp` / `PageDown` | Add / remove ten steps |
| `Home` / `End` | Jump to `min` / `max` when defined (otherwise the caret moves) |

Key handling is skipped during IME composition.

## Mobile

- The stepper buttons are not rendered on touch devices: half-height buttons cannot be 44px targets. The numeric keypad is requested instead (`inputMode="decimal"`, or `"numeric"` when `precision` is 0).
- The iOS numeric keypads have no minus key. If negative values are needed on phones, pass `inputMode="text"`.
- The `sm` size keeps a 16px font on touch so iOS does not zoom on focus.
