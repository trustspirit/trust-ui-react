# Carousel

Horizontally swipeable slides. The track is a native scroll container with CSS scroll snapping, so touch momentum, trackpads and keyboard scrolling behave as they do everywhere else on the platform. JavaScript only tracks the current slide and scrolls for the buttons.

## Slides per view

A fractional `slidesPerView` shows a peek of the next slide, which tells touch users there is more to swipe to. `gap` uses the spacing scale (`--tui-gap-1` to `--tui-gap-6`).

## Loop and arrows

With `loop`, next on the last slide scrolls back to the first (no cloned slides, so the scroll visibly rewinds). `showArrows="hover"` reveals the arrows only while the carousel is hovered or focused.

<ComponentPreview code={`<Carousel aria-label="Featured" loop showArrows="hover">
  …
</Carousel>`}>
  <div style={{ width: '100%', maxWidth: 480 }}>

## Auto-play

`autoPlay` takes an interval in milliseconds and renders a pause/play button. Rotation pauses while the pointer is over the carousel, while focus is inside it and while the page is hidden. It never runs when the user asks for reduced motion. Without `loop` it stops at the last slide.

<ComponentPreview code={`<Carousel aria-label="Announcements" autoPlay={4000} loop>
  …
</Carousel>`}>
  <div style={{ width: '100%', maxWidth: 480 }}>
    <Carousel aria-label="Announcements" autoPlay={4000} loop>
      <Carousel.Slide><Panel n={1} /></Carousel.Slide>
      <Carousel.Slide><Panel n={2} /></Carousel.Slide>
      <Carousel.Slide><Panel n={3} /></Carousel.Slide>
    </Carousel>
  </div>
</ComponentPreview>

## Controlled

```tsx
const [index, setIndex] = useState(0);

<Carousel aria-label="Featured" index={index} onIndexChange={setIndex}>
  …
</Carousel>
```

`onIndexChange` also fires when the user swipes to another slide.

## Accessibility

Follows the basic variant of the WAI-ARIA carousel pattern.

- Root: `role="region"` with `aria-roledescription="carousel"` and the name you pass in `aria-label` or `aria-labelledby`. Always give it one.
- Each slide: `role="group"` with `aria-roledescription="slide"` and a name from `slideLabel` ("2 of 5").
- Previous and next are buttons, disabled at the ends unless `loop` is set. Their icons mirror in right-to-left layouts.
- Dots are buttons in a group; the current one has `aria-current="true"` and is longer as well as darker, so it is not marked by colour alone.
- The track is focusable so it can be scrolled from the keyboard. It is a live region: `aria-live="off"` while rotating and `polite` when rotation is paused or absent, so slide changes made with the buttons are announced.
- In a one-slide view, slides that are off screen are `inert`, so Tab never moves into content that cannot be seen. Fractional, multi-slide and `auto` views leave their slides alone because several are visible at once.
- With `autoPlay`, the pause/play button satisfies WCAG 2.2.2 (Pause, Stop, Hide). It comes first in the control row.
- Programmatic scrolling is instant instead of smooth under `prefers-reduced-motion`.

| Key | Action |
| --- | --- |
| `ArrowRight` / `ArrowLeft` | On the track: next / previous slide (swapped in right-to-left layouts) |
| `Home` / `End` | On the track: first / last position |
| `Enter` / `Space` | Activate the focused arrow, dot or pause button |

Arrow keys pressed inside a control within a slide are left to that control.

## Mobile

- Swiping is native scrolling with scroll snapping: it keeps momentum, never fights vertical page scrolling, and does not trigger the browser's back gesture at the ends (`overscroll-behavior-x: contain`).
- By default the arrows are hidden on touch devices, where swiping is the affordance. Pass `showArrows` to force them on. Use a fractional `slidesPerView` to hint that more slides exist.
- Dots are small but each has a 44px touch area; so do the arrows and the pause button.
- In a one-slide view a fast swipe advances a single slide (`scroll-snap-stop: always`).
- Works in right-to-left layouts: the first slide is on the right and the keys follow the visual direction.
