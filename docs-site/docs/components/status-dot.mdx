# StatusDot

A small dot that shows presence or severity next to a name, a row or a heading.

## Basic Usage

<ComponentPreview code={`<StatusDot variant="success" label="Online" />`}>
  <StatusDot variant="success" label="Online" />
</ComponentPreview>

## Variants

`neutral` is ink grey and `accent` follows `--tui-accent` (ink unless the app sets a brand colour).

<StatusDot variant="success" label="Online" />
<StatusDot variant="warning" label="Degraded" />
<StatusDot variant="danger" label="Down" />
<StatusDot variant="accent" label="New" />`}>

  <StatusDot variant="success" label="Online" />

## Pulse

`pulse` adds a thin ring that expands and fades, for a status that is live right now. Use it for one or two dots on a screen, not for every row.

<ComponentPreview code={`<StatusDot variant="success" label="Syncing" pulse />`}>
  <StatusDot variant="success" label="Syncing" pulse />
</ComponentPreview>

## Accessibility

- The dot has `role="img"` and `aria-label` set from `label`, which is required. Write the status itself ("Online", "Payment failed"), not the colour.
- Colour alone does not reach everyone who can see the dot. Where the status matters, show it as visible text next to the dot as well; if that text says the same thing as `label`, pass `aria-hidden` to the dot so it is not read twice.
- The dot is not a live region. If the status changes while the user is on the page and they need to know, announce it separately.
- No keyboard interaction — the dot is not focusable.
- `pulse` stops under `prefers-reduced-motion`; the dot itself never fades, so the status colour is always fully visible.
- In forced-colors mode the dot is drawn in the system text colour. Variants are then indistinguishable by colour, which is another reason to pair it with text.

## Mobile

- The dot is 6px (`sm`) or 8px (`md`) and is not interactive. Do not attach click handlers to it; make the surrounding row or a button the target instead.
- It does not shrink inside flex rows, so it stays round next to long, wrapping text.
