# TextArea

A multi-line text input that grows with its content, with an optional character counter. It shares its label, helper text, error wiring and surface with the other fields.

## Auto resize

By default the textarea starts at `rows` lines, grows with its content up to `maxRows`, and scrolls after that.

<ComponentPreview code={`<TextArea
  label="Notes"
  helperText="Starts at 2 lines, scrolls after 6"
  rows={2}
  maxRows={6}
  fullWidth
/>`}>
  <TextArea
    label="Notes"
    helperText="Starts at 2 lines, scrolls after 6"
    rows={2}
    maxRows={6}
    fullWidth
  />
</ComponentPreview>

With `autoResize={false}` the height is fixed at `rows` and the user can drag the corner to resize it vertically.

<ComponentPreview code={`<TextArea label="Notes" autoResize={false} rows={4} fullWidth />`}>
  <TextArea label="Notes" autoResize={false} rows={4} fullWidth />
</ComponentPreview>

## Character count

Setting `maxLength` shows a counter. Pass `showCount={false}` to keep the limit without the counter.

<ComponentPreview code={`<TextArea
  label="Bio"
  helperText="Shown on your public profile"
  maxLength={80}
  defaultValue="Keep it short."
  fullWidth
/>`}>
  <TextArea
    label="Bio"
    helperText="Shown on your public profile"
    maxLength={80}
    defaultValue="Keep it short."
    fullWidth
  />
</ComponentPreview>

The browser stops typing at `maxLength`, but a value that arrives from elsewhere (a saved draft, a controlled value) can be longer. The counter then turns to the danger colour and the field is marked invalid.

<ComponentPreview code={`<TextArea
  label="Summary"
  maxLength={20}
  defaultValue="This draft is longer than the limit."
  fullWidth
/>`}>

## Value

`onChange` receives the native change event; `onValueChange` receives the text.

```tsx
const [value, setValue] = useState('');

<TextArea label="Message" value={value} onValueChange={setValue} />
```

## Accessibility

- A native `textarea` named by its `label`. `hideLabel` hides the label visually but keeps it as the name.
- Helper text or the error message is linked with `aria-describedby`; the error state sets `aria-invalid`. The error element is a polite live region.
- The counter is part of the description, so it is read when the field receives focus. A separate polite live region announces the remaining characters only when the text is within the last 20% of the limit (at most 10 characters) or over it, so it does not speak on every keystroke. Override the sentence with `countAnnouncement`.
- The count does not change in the middle of an IME composition; it updates when the composition ends.
- `required` sets the native attribute and `aria-required`; the asterisk is decorative.

| Key | Action |
| --- | --- |
| `Enter` | Insert a line break |
| `Tab` | Move focus out of the field |

## Mobile

- The `md` size uses `--tui-font-size-base`, which is 16px on touch devices, and `sm` keeps a 16px minimum there, so iOS does not zoom the page on focus.
- Auto resize measures once per change of value or width. The field never grows beyond `maxRows`, so it cannot push the submit button off screen under the on-screen keyboard; pair it with `KeyboardAvoidingView` in full-screen forms.
- The resize handle of `autoResize={false}` is hard to grab on touch. Prefer the default there.
