# Combobox

A searchable single-select where the user types freely and picks from a filtered list. Use it for long or server-backed lists; for a short static list, `Select` with `searchable` is enough.

## Async search

`onSearch` receives the typed text. Load the options yourself and pass them back through `options`, with `loading` while the request runs. Pass `filter={null}` so results the server already filtered are shown as they are, and `minQueryLength` to wait for a few characters.

```tsx
function StockPicker() {
  const [options, setOptions] = useState<ComboboxOption[]>([]);
  const [loading, setLoading] = useState(false);
  const [value, setValue] = useState<string | null>(null);

  const search = async (query: string) => {
    setLoading(true);
    setOptions(await fetchStocks(query));
    setLoading(false);
  };

  return (
    <Combobox
      label="Stock"
      options={options}
      loading={loading}
      onSearch={search}
      filter={null}
      minQueryLength={2}
      value={value}
      onChange={setValue}
    />
  );
}
```

`onSearch` is called on every change, including text that is still being composed with an IME, so Korean input filters syllable by syllable. Debounce and discard stale responses in your own code. The component remembers the selected option, so its label stays visible when later results no longer contain it. A controlled `value` whose option has never been in `options` is shown as the raw value.

## Text and selection

- Typing never changes the value; only picking an option does.
- On blur, text that does not match the selected option reverts to the selected label. Text that was deleted completely clears the selection.
- The clear button and `Escape` (with the list closed) clear both the text and the selection.
- With `name`, the selected `value` is submitted through a hidden input.

## Accessibility

Follows the WAI-ARIA "editable combobox with list autocomplete" pattern.

- The input has `role="combobox"`, `aria-autocomplete="list"`, `aria-expanded`, `aria-controls` and `aria-activedescendant`. DOM focus stays in the input the whole time.
- The popup is a `listbox` named by the field label; items are `option` elements with `aria-selected` and `aria-disabled`.
- The result count, the empty text and the loading text are announced through a polite live region.
- Helper text and error message are linked with `aria-describedby`; the error state sets `aria-invalid`.

| Key | Action |
| --- | --- |
| `ArrowDown` / `ArrowUp` | Open the list; move to the next / previous option, skipping disabled ones |
| `Home` / `End` | First / last option while an option is active (otherwise the caret moves) |
| `Enter` | Select the active option |
| `Escape` | Close the list; when already closed, clear the text and the selection |
| `Tab` | Close the list without selecting and move on |

All key handling is skipped during IME composition, so the `Enter` that commits a Hangul syllable does not select an option.

## Mobile

- Touch devices get the same inline popup (no separate sheet), so the keyboard and the results are visible together. Options are at least 44px tall and the clear button is 44px wide.
- The popup closes when the page is scrolled; scrolling inside the list does not close it, and neither does the scroll the browser performs while the on-screen keyboard opens.
- The popup takes the width of the field and stays inside the viewport, flipping above the field when there is no room below.
- The `sm` size keeps a 16px font on touch so iOS does not zoom on focus.
