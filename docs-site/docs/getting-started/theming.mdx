# Theming

trust-ui v2 theming is plain CSS custom properties keyed off a handful of `data-*` attributes on `<html>`. There is no runtime color computation — nothing derives a hover shade or a tint from a base color for you. Every state a component can render has to resolve to a token that's actually defined somewhere in the cascade.

Two independent **axes** control which token values are active, and two optional **layers** sit on top of them.

## Axis: `data-theme`

`light` or `dark`. Selects which mapping of the neutral palette onto `--tui-paper`, `--tui-ink`, `--tui-rule`, and the rest is active — see [Colors](../design-tokens/colors.mdx) for the full token list per theme.

## Axis: `data-density`

`comfortable` (default) or `compact`. Controls control heights and inner padding only — never color. Switching density does not touch a single color token. See [Spacing & Radius](../design-tokens/spacing.mdx#inner-padding--density-linked).

## Setting the axes

`ThemeProvider` writes both attributes onto `<html>` and exposes them through `useTheme()`:

```tsx
import { ThemeProvider, useTheme, Button } from 'trust-ui-react';

function App() {
  return (
    <ThemeProvider defaultTheme="light" defaultDensity="comfortable">
      <YourUI />
    </ThemeProvider>
  );
}

function ThemeToggle() {
  const { theme, toggleTheme, density, setDensity } = useTheme();
  return (
    <>
      <Button onClick={toggleTheme}>Switch to {theme === 'light' ? 'dark' : 'light'}</Button>
      <Button onClick={() => setDensity(density === 'compact' ? 'comfortable' : 'compact')}>
        Switch to {density === 'compact' ? 'comfortable' : 'compact'}
      </Button>
    </>
  );
}
```

If `defaultTheme` is omitted, the initial value is read once from `prefers-color-scheme` at first render. That read happens only once — `ThemeProvider` does not keep listening for OS-level changes afterward, and it does not persist a user's choice anywhere. If your app wants either of those, do it yourself: call `setTheme` from your own `matchMedia` listener, or write/read the value from `localStorage` around the provider.

## Layer: `market.css` (optional)

Financial screens that color price deltas by rise/fall need one more axis, `data-market` (`kr` default, `us`), and the stylesheet that reads it:

```tsx
import 'trust-ui-react/market.css';
```

`ThemeProvider` accepts `defaultMarket` and `useTheme()` exposes `market`/`setMarket` the same way it does theme and density. Full color mapping and both themes' variants: [Colors → Market colors](../design-tokens/colors.mdx#market-colors--optional-layer).

## Layer: brand accent

Out of the box there's no brand hue — `--tui-accent` resolves to `--tui-ink`, so a fresh install renders as pure grayscale:

```css
--tui-accent: var(--tui-ink);
--tui-on-accent: var(--tui-on-ink);
--tui-accent-hover: var(--tui-ink-2);
```

An app that wants a brand color overrides these three. **Override `--tui-accent-hover` alongside `--tui-accent` — v2 does not compute a hover shade from the base color.** Overriding only `--tui-accent` leaves every hover/active state resolving to the ink-based default, which will visibly clash with whatever hue you just set:

```css
/* my-brand-overrides.css — load AFTER trust-ui's styles.css */

[data-theme='light'] {
  --tui-accent: #ff5c2c;
  --tui-accent-hover: #e8501f;
}

[data-theme='dark'] {
  --tui-accent: #ff7a52;
  --tui-accent-hover: #ff9272;
}
```

```ts
// Your app entry
import 'trust-ui-react/styles.css';
import './my-brand-overrides.css'; // always after trust-ui
```

Nothing else needs to change — every component that renders an accent (Button, Switch, Checkbox, focus rings, …) reads `--tui-accent`/`--tui-on-accent`/`--tui-accent-hover` and picks the override up automatically. Details: [Colors → Accent](../design-tokens/colors.mdx#accent).

## Mobile considerations

- Form `<input>`/`<textarea>`/`<select>` get a minimum 16px font size on `pointer: coarse` devices — this prevents iOS Safari's auto-zoom on focus.
- Hover effects are wrapped in `@media (hover: hover)` so they don't get stuck after a tap on touch devices.
- `prefers-reduced-motion: reduce` is respected globally — see [Motion → Reduced motion](../design-tokens/motion.mdx#reduced-motion).
- iOS notch and home-indicator insets are handled via the safe-area tokens. Use [`<SafeAreaView>`](../design-tokens/spacing.mdx#touch-targets--safe-area) for fullscreen layouts.

## Multi-brand setup

For multiple brands in one app, scope the accent override to a custom attribute or class instead of `[data-theme]`. Remember both tokens per brand, per theme, if the brand hue needs to differ between light and dark:

```css
[data-brand='alpha'] {
  --tui-accent: #635bff;
  --tui-accent-hover: #4f3fe0;
}
[data-brand='beta'] {
  --tui-accent: #ff5c2c;
  --tui-accent-hover: #e8501f;
}
```

```tsx
<section data-brand="alpha">{/* Alpha components */}</section>
<section data-brand="beta">{/* Beta components */}</section>
```

Each section's components consume the locally-overridden tokens with no extra wiring.
